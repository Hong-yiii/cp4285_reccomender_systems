Study recommendation quality on previously learned tasks during continued updates, potentially varying model capacity and incoming domain composition. The team wants independent model exploration converging on shared, inspectable evaluation. Decline, stability and improvement are all valid outcomes. Do not promise forgetting or neural superiority.

**User-requested integration:** apply the two-package/ABC paradigm to the actual implementations on `main`, preserve them, and open a PR into `main`. ## Implemented now

- Existing uv-managed Python 3.12 runtime and locked dependencies; no new framework or dependency.
- Shared generic `Recommender` ABC: `train`, `begin_continuation`, `score`, `describe`, and default full-state in-memory `fork`.
- `SASRecLearner` wraps the unchanged original-architecture PyTorch network. The actual pilot uses the ABC for updates and scoring. Initial training retains uniform user resampling and all-position sampled loss; continuation retains fresh-target-only loss, with Adam reset once and then preserved.
- Owned Python and CPU/device Torch RNG state, pure scoring, sequential fork isolation and copied optimizer parameter bindings. Tests exercise CPU; accelerator backends require their own validation.
- `IncrementalQRSVD` implements the ABC; the real classical stream calls it for fresh user-row chunks and one phase transition. It retains its basis, singular values and owned NumPy RNG.
- All batch classical kernels and their independent refit sweeps remain available. `MarkovQRSVD` is **not** incremental and still retains the full sparse transition table. No fake continuation adapter is provided.
- Both protocol-specific evaluators live in `experiment/`. **They remain scientifically different**, including splits, vocabularies, seen masking, ties and learning units. A shared ABC does not make scores comparable.
- Existing validated downloader/audit, holdout isolation, validation-selected SASRec weights, checkpoint reload, frozen control and create-only artifacts are retained.
- Runnable development guide and `notebooks/01_shared_lifecycle.ipynb`, with executable documentation and model-lifecycle checks in addition to the existing tests.

The tagged boilerplate's single-target `Example` contract and generic runner are **not** copied into this integration: enforcing them unchanged would silently alter main's all-position SASRec training and classical row-chunk semantics. Neither is presented as the final common benchmark.

**Not implemented:** neural B interfaces/mixed updates, common classical/neural evaluation, multi-seed aggregation, interrupted-run resume or a finalized experiment matrix. Checkpoints save weights/optimizer/cursor and owned RNG, but the CLI cannot resume them. Sequential in-memory forks are not thread-safe global-RNG isolation. Owned RNG and avoiding a throwaway network initialization during reload change historical continuation random trajectories; use new run artifacts and record the code revision.

## LLM continual-recommendation workstream — 19 October 2026

User-requested and exploratory; **not** a team-confirmed protocol change. The user chose to replicate PESO (Yoo et al., ICLR 2026, arXiv 2510.25093) before choosing an LLM extension. See [PESO-REPLICATION.md](docs/PESO-REPLICATION.md).

- Implemented: a Modal launcher and a Runpod pod runner. Both use Python 3.10 instead of upstream's 3.9 and one GPU per stage with gradient accumulation 4 (same effective batch 32), and keep all other upstream pins; our evaluator, which pairs any saved block state with any block's test users and dumps per-user top-10s; `cp4285 flips`, which reports the retention matrix, backward transfer, kept/lost/gained counts, McNemar tests, forgetting events and user-group slices; and a new/dormant/continuing labeller.
- Checked in upstream code and data: the PESO penalty covers only the LoRA matrices, while the item-token embeddings and output layer train unpenalized; there is no target leakage across blocks; the semantic-ID index covers items that arrive later; the released datasets differ from the paper's; only seed 42 is used; and the released KL penalty is numerically negligible (about 10⁻⁶ against a loss of about 2, measured from checkpoints), because its softmax over each matrix's entries divides it by the matrix size.
- Result, 20 October (three seeds): Pretrain and single evolving LoRA reproduce Table 2 within about 5% (NDCG@10 0.0137 and 0.0147 against 0.0131 and 0.0150). PESO does not beat single evolving LoRA: NDCG@10 0.0146 ± 0.0007 against the paper's 0.0162, with a paired PESO − LoRA difference of −0.0001 ± 0.0002 against the claimed +0.0012. Seed variation is as large as the claimed gain. Infrastructure issues (two-GPU races, Modal preemption, a Runpod host outage) are documented in the replication record.
- Analysis, 20 October (seed 42): the transfer matrix shows backward transfer of −0.0038 (single LoRA) and −0.0061 (PESO) NDCG@10. About 45% of earlier top-10 hits are lost at each update and replaced by roughly as many new ones. PESO and single LoRA differ on only 11–27 users per block, and no pair is significant. A Jacobian-lens probe reads the target's first item code from layer 4 and finds PESO's internal drift equal to single LoRA's.
- Deliverables: progress update `docs/updates/2026-10-20-peso-replication.md` (meeting-notes format); `notebooks/02_peso_replication.ipynb`, with metric files and aggregate seed-42 reports committed under `replication/peso/results/`; and `notebooks/03_peso_colab.ipynb`, which re-evaluates trained seed-43 weights from a GitHub release. It is under test on a personal fork; the team-repo release is still a draft.
- Analysis, 21 October (seed 42):
  - **Item-level J-lens** (all four codes, 15 layers): forgetting sits in the broad first code, while the exact-item codes improve over updates; there is no hidden retention against a permutation baseline.
  - **Calibration:** even the paper's Eq. 12 at λ = 8 pulls about 10⁻⁴ as hard as the task gradient.
  - **O8, a size-normalized penalty at λ = 400:** backward transfer −0.0029 against −0.0038, with no own-state (Table 2) gain. The per-user difference is not significant (p = 0.28). The penalty shrinks the inner J-lens drift by 26–50%, and the newest block's exact-item codes are learned less well.
  - **Colab notebook 03** passed a fresh-environment test.
- Ready, 21 October (not yet run): O2, an item-layer penalty (`pod_run.py variant --method peso-size-w<λ>-i<μ>`, with μ from the new `item-drift` stage), and the λ sweep (`peso-size-w100`, `peso-size-w1600`).
- Category targets, 22–24 October (user-requested, done): every PESO event is renamed to its item's PR 14 level-2 subcategory, 30 tokens, 480–1,350 times denser than items but half of all test targets are one category ([PESO-REPLICATION.md](docs/PESO-REPLICATION.md#category-targets-from-pr-14--22-october-2026)). `category_index.py` builds the data, and `category_report.py`/`category_summary.py` score dumps with the shared `cp4285.experiment.metrics` beside popularity and history baselines. Runs use the NUS SoC Slurm cluster through `replication/peso/slurm/`, with deterministic beam search, because the released beam sampling crashes on one-token targets (finding 11). Results, 24 October (seeds 42–44): every method beats the history and popularity baselines, but single LoRA and PESO gain nothing over Pretrain and forget nothing. The released item model, read as categories, falls below both baselines. Category-prefixed item IDs (seed 42) change nothing measurable ([PESO-REPLICATION.md](docs/PESO-REPLICATION.md#category-target-peso--24-october-2026-seeds-4244)).
- Granularity ladder, 24 October (done, experiment 1): levels 2–4 with three seeds each, plus two product seeds. The update gain grows smoothly with finer labels; forgetting appears only at products ([PESO-REPLICATION.md](docs/PESO-REPLICATION.md#granularity-ladder--24-october-2026-experiment-1-seeds-4244)).
- Corrupted-stream grid, 24–26 October (user-requested, done): 303 runs on PR 14 level-2 category blocks across Instruments, Video Games and CDs (30, 43 and 59 categories), three seeds. Attacks hit hard in the block they touch (bandwagon −2.1 ranks, relabel −7.7) and fade by block 4 (83–94% gone); 1% injected every block keeps the category up under isolated adapters, about a third of its first effect, and the only top-5 gain that persists to block 4 (+1.10 pp, 8/9); block 4 carries its own dose, and a shared adapter ends at clean. `condition` is adapter topology: `shared` is one adapter updated across blocks (the bandwagon effect reverses to +0.10 by block 4), `isolated` freezes one adapter per block and sums them (residue −0.13; relabel −1.18 against −0.09 shared). Demotion and vandalism do nothing ([PESO-REPLICATION.md](docs/PESO-REPLICATION.md#corrupted-stream-grid--2426-october-2026-seeds-4244)).
- Focused follow-up, 27 October (zero GPU, done; wave 1 launched): a metric-to-metric pass over the 303 grid runs (`replication/peso/grid_lattice.py` + `grid_drift.py`, results in `replication/peso/results/grid/`) relates dose → spike → residue → cost → stealth → drift. Headlines: spike → residue is strong only under isolated adapters (ρ +0.66 vs +0.27); the segment trigger's block-4 residue is group-targeted and stealthy (−0.62 ranks, 9/9, hidden by the average); drift does not explain the washout; the delete arms' over-correction is magnitude-true but direction-mixed. Wave 1 rare-target replication submitted on the cluster (18 runs, jobs 1023419–24, ~3.5 GPU-h): frequency-dependent forgetting for seeds 43–44. The low-and-slow-that-stop arm is deferred — the runner's `--placement` only accepts block|all|init, so "attack then stop" needs a placement change with tests. The dose-matched real-vs-fake arms were cut — the lattice shows per-lesson efficiency differs by kind, which reframes that question.
- Decoding and detectable effects, 23 October (released seed-43 weights, NUS SoC A100): six sampling draws move PESO − single LoRA NDCG@10 between −0.0010 and +0.0007. Deterministic decoding halves the smallest gap one seed can detect, from 0.0016 to 0.0007. About half of a user's single LoRA − Pretrain or forgetting difference persists across seeds, which sets a floor more seeds cannot lower ([PESO-REPLICATION.md](docs/PESO-REPLICATION.md#detectable-effects--23-october-2026-seed-43-five-more-draws)).
- New products, 23 October (experiment 3): neither PESO nor SASRec puts any of 1,246 never-trained products in its top 20; PESO alone hits rare products (0.6–0.7%) and aims at the right first code more often ([PESO-REPLICATION.md](docs/PESO-REPLICATION.md#new-products--23-october-2026-seed-43-and-sasrec-experiment-3)).
- Not done: O8 on more seeds and λ values, O2 and the other directions. Figures in notebook 02 wait on a plotting-dependency decision; notebook 03 uses Colab's own matplotlib. Upstream code has no licence: it lives only in ignored `local/peso/` and the run image. Results are on PESO's released Instruments blocks and are not our Electronics/Movies & TV results.

## Scientific invariants and unresolved decisions

- Preserve source identities and domain namespaces; never equate unrelated integer IDs or splice unrelated users' histories.
- Keep holdouts out of training targets and prefixes. The inherited neural cutoff pilot still uses a shared initial prefix for validation and retention, so its retention anchor is not automatically ordinary one-step next-event testing.
- Freeze each task's queries, targets, candidate catalogue and ranking policy across checkpoints. Select/tune on validation, not retention curves.
- Declare update/exposure units: a SASRec supervised target is not a complete user row for incremental SVD. Batch refits are not continual training.
- The provisional Amazon target is a reviewed item, not a purchase timestamp or ideal-recommendation ground truth. Review the feedback/rating filter.
- A larger B share at fixed total targets also reduces A exposure; that alone does not isolate harmful B gradients. Agree the mixture denominator, controls and shared-parameter mechanism.
- Historical SASRec, QR-Markov, category pair, capacities, cutoffs, @10 and budgets are implementation defaults/proposals, not newly confirmed October choices.
- Choose a common task/horizon, split/cohort, vocabulary/cold-start policy, candidates, metric/cutoff, model/capacity, schedules, seeds and affordable budgets before comparing models.
- Acquisition and expensive runs require explicit approval. Synthetic software checks are never Amazon results. Existing artifacts must not be overwritten.
